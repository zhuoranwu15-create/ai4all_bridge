> 关联：[campaign_codes_prd.md](campaign_codes_prd.md)、[agent_self_prd.md](agent_self_prd.md)、[agent_mission_and_orchestration_design](../../../architecture/products/zhaoxi/agent_mission_and_orchestration_design.md)

第一版目标人群：**① 恋爱幻想 / 乙女游戏人群（优先）**、**② 25-35 岁宝妈**。
尺度红线：**甜宠健康向**——保留心动/暧昧/独占的高浓度情绪，但不 PUA、不控制、不涉黄暴、不制造焦虑。

## 1. 方法论

### 1.1 底层原理：人设 = 目标人群"情感缺口"的镜像

这两类人群迷恋的不是某个具体角色，而是**现实里缺失的那种被对待的方式**。设计动作恒为：先定位缺口 → 造一个"专门补这个缺口"的角色。

| 人群 | 现实核心缺口（人群研究结论） | 对应人设"解药" |
|---|---|---|
| 乙女 / 恋爱幻想 | 现实男性"进步慢于女性觉醒"；要 **尊重 + 专一 + 会示弱 + 平等博弈**，反感"爹味/油腻" | 新型霸总、覆面系硬汉、极致专一竹马——**女性凝视**下为她设计 |
| 25-35 宝妈 | 不缺钱，缺 **"说了没人听懂/没人回应"的表达型孤独**；渴望被看见、被夸、被回应、被当成"女孩"而非只是妈妈 | "事事有回应"的理想搭档、把她当女孩宠的治愈系——**情绪价值优先于功能** |

两条北极星：
- **乙女**：男主的外形与情感设定都为女性欲望服务（女性凝视）。
- **宝妈**：一句"辛苦了"胜过"我养你"；"事事有回应"胜过物质供养。

### 1.2 人设四件套（对齐系统真实字段）

每套人设都落到系统可配置的四层（详见 §2 映射）：

- **SOUL（人格内核）** → `soul_preset_key` 选中的 `app/soul_templates/<key>.md`。决定"他是谁、怎么说话、脾气、柔软处、底色"，是一致性的根。注入上限 **3000 字**。
- **IDENTITY（身份/名字）** → `ai_name_preset`（≤24 字）写进 `IDENTITY.md`。注入上限 **1500 字**。
- **MISSION（使命）** → `mission_id` 选中的 `MISSION_TEMPLATES` 条目 + `mission_templates/<slug>.md`。给角色一个"和用户一起做的事 + 一个悄悄在想的问题"。注入上限 **1500 字**。
- **开场白 + 边界** → onboarding 首条 + SOUL 内的红线约束。决定 3 秒留存与人设不崩。

### 1.3 内容营销打法：场景 × 标签矩阵

最可复用的一条：**"场景 + 标签"内容矩阵**——不讲功能，讲场景里的情绪价值。

- **拆场景**：深夜 emo 局 / 失恋陪聊局 / 异地恋替代局 / 乙女梦男局 / 宝妈委屈局 / 被夸一下局……每个场景 = 一批笔记。
- **内容形式**：晒"对话截图"最自传播——"AI 男友说的这句话我哭了"类图文。
- **官方话题**：`#和我的AI男友日常` `#乙女养成计划` `#今天也被AI夸了`，沉淀 UGC。
- **主阵地**：小红书为主，公众号/朋友圈/视频号为辅。

### 1.4 完整漏斗

```
小红书图文种草（场景+情绪）
  → 话题聚合 + 评论区/主页软钩子（合规，见 §6）
  → 落地页（对应人设的 campaign 注册链接 code）
  → 注册即 apply_campaign_code_attribution 写死人设快照（SOUL+名字+mission）
  → AI 首条开场白接住
  → 前 3 轮对话建立"他真的懂我"钩子
  → 留存 / 复访
```

## 2. 系统落地映射（人设 → campaign 字段，代码级）

一个营销活码（`campaign_codes` 表，`app/products/zhaoxi/infrastructure/persistence/campaign.py`）通过四个知识旋钮把一条注册链接绑定到一套人设。注册时 `apply_campaign_code_attribution()` 写死快照到 `account_campaign_attribution`（**写入即定型**，之后改活码不影响已注册账号）。

| Campaign 字段 | 作用 | 本方案取值来源 |
|---|---|---|
| `code` | URL-safe 短码 `^[A-Za-z0-9_-]{1,64}$`，拼进营销链接 | 每套人设一个，见各人设"Campaign 配置" |
| `campaign_key` | 活动分组标签（自由文本） | `otome_2026q3` / `mom_2026q3` |
| `ai_name_preset` | AI 名字（≤24 字，单行）→ 写进 `IDENTITY.md` 的 `- AI 名字：X` | 各人设名字 |
| `soul_preset_key` | 选 `app/soul_templates/<key>.md`，须在 `user_profiles.py` 的 `_SOUL_TEMPLATES` 名单里注册 | **本方案需新增 5 个 SOUL 模板 key** |
| `mission_id` | 选 `MISSION_TEMPLATES` 条目 | 乙女→`mission_003`；宝妈→`mission_004`；兜底→`mission_001` |
| `onboarding_script_variant` | onboarding 流程变体 | `otome_v1` / `mom_v1`（如无对应变体先留空，走默认） |
| `status`/`valid_from`/`expires_at` | 状态与有效期（默认 3 个月） | 上线时填 |

> **关键约束（探查确认）**：
> 1. 现有 6 个 SOUL 文件里，只有 `blank/xiaotaiyang/xiaoyueya/ju` 被 `_SOUL_TEMPLATES` 注册为可选 preset。**新增 SOUL 模板必须：落 `.md` 文件 + 在 `user_profiles.py:~22` 的名单追加 key**，否则活码校验 `_validate_soul_preset_key` 会拒绝。
> 2. 现有 6 个 SOUL 全是"无性别陪伴"，**没有恋爱向男性人设**——乙女向必须新增带性别("他")的 SOUL 模板。
> 3. 名字写入顺序：先 `write_ai_name_to_identity` 再 `apply_soul_preset`（SOUL 渲染时会从 IDENTITY 回读名字填 `{name_clause}`）。此顺序在 `apply_campaign_code_attribution` 已保证。
> 4. SOUL 模板用占位符 `{name_clause}`（AI 名字，缺省"我"）和 `{user_clause}`（用户称呼，缺省"这个用户的"），渲染时替换。
