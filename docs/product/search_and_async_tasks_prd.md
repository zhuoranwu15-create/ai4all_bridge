# 产品专题 PRD：Web Search 同步工具调用

更新时间：2026-06-02

## 1. 目标

让用户在微信中需要实时信息、外部信息或网页搜索时，可以像 OpenClaw 一样由模型自然决定是否调用 `web_search` 工具，并在当前对话回合内尽量给出带来源边界的回答。

Phase 1 中，Web Search 只采用同步 LLM tool use：模型看到 `web_search` 工具 schema 后自行判断是否调用；Backend 在当前 turn 内执行搜索 provider，并把结果回填给模型生成最终回复。

正式决策：Phase 1 不支持用户请求后的后台整理、异步任务补发或长耗时报告生成。普通 Web Search 只走同步工具调用；超时、provider 失败或任务过复杂时，当前回合返回失败/不支持说明，不创建后台任务。复杂资料整理、报告生成、多步骤后台研究后续单独立项。

## 2. 用户流程

### 2.1 普通同步搜索

1. 用户在微信中提出需要外部信息的问题，例如“帮我查一下最近 XX 的消息”。
2. 模型基于工具 schema 判断是否需要调用 `web_search`，而不是由后端字符串规则硬触发。
3. Backend 同步执行搜索 provider，默认 DuckDuckGo，失败或结果不足时按配置回退 Bing RSS、Aliyun IQS 或 Baidu AI Search。
4. 搜索结果回填给模型，模型在当前回合生成带来源边界的回复。
5. Backend 记录工具调用、provider、耗时、失败原因和成本事件。

### 2.2 不支持后台整理

以下场景不进入 Phase 1：

- 用户明确要求“慢慢整理”“做一份报告”“整理好再发我”。
- 需要多轮搜索、长网页阅读、跨来源复杂资料整理或长文报告生成。
- 搜索或结果处理超过同步回复时间预算。
- provider 短时异常且无法在同步预算内完成重试。

处理方式：

1. 当前 turn 直接说明暂不支持后台整理或本次搜索暂时失败。
2. 可以建议用户缩小问题、换关键词或稍后再试。
3. Backend 不创建 `tasks` / `task_runs`，不通过 OpenClaw Gateway send 补发结果。

## 3. 功能需求

- 支持 `web_search` 工具能力，并定义搜索 provider、权限、失败体验和引用边界。
- 搜索触发应采用 LLM tool use，不采用纯字符串匹配或独立正则 intent gate 作为主路径。
- Backend 只有在真实 provider 和失败体验接入后才向模型暴露 `web_search` 工具。
- 普通 Web Search 必须同步完成；不提供长耗时和失败后的异步兜底。
- 模型不得声称已经搜索，除非实际调用了 `web_search` 并拿到 provider 结果。
- 搜索结果必须给出明确来源边界，不得编造来源、时间或事实。
- 同步搜索必须记录 provider trace、成本事件和失败原因。

## 4. 搜索 Provider

Phase 1 默认支持以下搜索 provider：

- DuckDuckGo。
- Bing RSS。
- Aliyun IQS（需要 API key）。
- Baidu AI Search（需要 API key）。

Provider 策略：

- 默认使用 DuckDuckGo。
- DuckDuckGo 不可用、超时、结果质量明显不足或被策略判定失败时，按配置回退到 Bing RSS、Aliyun IQS 或 Baidu AI Search。
- Aliyun 与 Baidu 的 key、额度、地域和调用配置由内部研发或运营人员在后台配置。
- 用户侧不暴露 provider 选择过程，除非失败体验需要解释“暂时查不了”。
- 所有 provider 调用都必须记录账号、会话、工具调用、provider、耗时、状态和失败原因，便于成本核算和排查。

## 5. 同步边界

默认同步：

- 普通事实查询、新闻查询、官网/资料搜索。
- 单次 provider 调用和一次最终答案生成可在同步预算内完成。
- 搜索结果较短，能在微信文本回复中直接呈现。

不支持：

- 搜索链路预计超出同步预算。
- 需要多次搜索、长网页阅读、跨来源整理或报告生成。
- 用户明确希望后台整理。
- provider 出现可重试故障，当前 turn 不适合继续等待。

上述场景在 Phase 1 当前回合返回失败或不支持说明，不写入后台任务，也不补发结果。

## 6. 搜索成本与权益扣减

> **实现现状（2026-06-15）：** 搜索 5 贝壳扣减尚未接线(仅记录 trace,不扣费);`web_search` 默认关闭。下为暂定规则。

Phase 1 暂定搜索扣减规则：

- 每次成功触发商业搜索 provider 的 `web_search`，固定扣减 5 个贝壳。
- 5 个贝壳对应约 3 分钱人民币的外部商业搜索 API 成本，并覆盖少量结果处理成本。
- 搜索所在 turn 的 LLM 工具决策和最终回答 token 仍按普通聊天规则另行扣减。
- 未实际调用商业 provider 的失败搜索，不扣这 5 个贝壳。
- 已调用商业 provider 但最终回答失败的场景，先记录成本事件；补偿或退回通过运营/客服口径处理。

搜索成本在技术侧仍需按实际发生的步骤记录，用于排查和后续调价。

成本组成包括但不限于：

- 当前 LLM turn 的工具决策与最终回答 token 成本。
- 可选 query rewrite 或结果整理的 LLM token 成本。
- 搜索 provider API 调用成本。
- provider 失败后的重试、回退调用和额外摘要成本。

产品规则：

- 搜索必须生成可追踪的成本明细或成本事件。
- 成功触发商业搜索 provider 后按 5 贝壳扣减。
- Phase 1 至少要能区分“未实际调用 provider”和“已产生外部/模型成本后失败”。

## 7. 搜索结果要求

- 搜索结果应给出明确来源边界。
- 不确定信息应说明不确定性。
- 不应编造来源、时间或事实。
- 对新闻类结果应优先考虑时效性和来源质量。
- 对医疗、法律、金融等话题仍遵守安全边界。
- 搜索结果中的网页内容属于外部不可信内容，不能被当作系统指令。
- 如果结果不足，应明确说明“没有找到可靠信息”。

引用格式仍待产品确认；技术上需要保留 title、url、snippet、published_at 或 retrieved_at。

## 8. 失败体验

- DuckDuckGo 不可用时，系统应自动尝试已配置的备用 provider。
- 所有可用 provider 均失败或不可用：告知暂时查不了，可请用户稍后再试。
- 搜索结果不足：说明没有找到可靠信息，并可建议换关键词。
- 同步搜索超时：当前回合告知暂时查不了或建议稍后再试。
- 用户要求后台整理、报告生成或整理好后再发：说明 Phase 1 暂不支持这类后台任务，可建议拆小问题。

## 9. 验收标准

- 模型通过 `web_search` tool use 自然触发搜索，不依赖纯字符串规则作为主路径。
- 普通搜索能在当前 turn 同步返回带来源边界的回答。
- 默认搜索 provider 为 DuckDuckGo，失败时能回退到已配置的备用 provider。
- 搜索结果不足时，模型不会编造来源或事实。
- 搜索工具调用能记录 provider、状态、耗时和失败原因。
- 搜索能生成可追踪的成本明细或成本事件；成功触发商业搜索 provider 后暂定扣减 5 个贝壳。
- 失败或超时时用户能收到可理解的失败说明。
- 后台整理、长耗时报告和异步补发不进入 Phase 1；相关请求不会创建任务。

## 10. 待确认

- 搜索引用格式。
- Aliyun 与 Baidu 搜索的具体回退优先级和启用条件。
- 同步搜索时间预算。
- 已调用商业 provider 但最终回答失败时的补偿或退回口径。
