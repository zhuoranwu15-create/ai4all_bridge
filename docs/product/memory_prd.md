# 产品专题 PRD：记忆与上下文

更新时间：2026-05-27

## 1. 目标

让用户感受到 AI 有连续性和基本个人化，但避免无边界沉淀、错误记忆污染和账号串线。记忆机制要学习 OpenClaw 的分层记忆与 Dream/Dreaming 思路，并适配 AI4ALL 一对多服务。

产品上，记忆不是单一文件或单一功能，而是由三类能力共同组成：

- 当前聊天能接得住：短期上下文。
- 重要信息不容易忘：长期但精简的常驻记忆。
- 时间跨度很长时还能想起来：需要检索、提取、动态装载的历史记忆。该能力 Phase 1 作为可选能力，不阻塞内测发布。

## 2. 产品范围

Phase 1 至少支持：

- 账号级短期上下文。
- 以凌晨 4 点为日界线的 daily notes。
- `MEMORY.md` 为主体的长期精简记忆。
- `SOUL.md`、`USER.md`、`IDENTITY.md` 等账号上下文中与用户/AI 设定相关的稳定信息。
- Dream/Dreaming 风格的 session 压缩和长期记忆蒸馏。
- 超长 session 的压缩与新 session 延续。
- 运营侧查看、重置、禁用记忆。
- 用户明确纠正或拒绝记忆时，能更新、删除或降权。

Phase 1 可选支持：

- 基于历史 daily notes 的检索式记忆能力的产品框架和初步实现。

用户侧记忆管理入口 Phase 1 可简化，但长期需要支持用户自主查看和管理记忆。

## 3. 记忆逻辑分层

### 3.1 短期上下文

短期上下文是当前对话 session 中 AI 能直接“接得住”的内容。它类似人和人连续聊天时，对方刚刚说过的话、当前话题、正在推进的问题。

用途：

- 保证多轮对话连贯。
- 理解指代、省略和当前话题。
- 支撑当前 session 内的连续陪伴体验。

产品规则：

- 默认从当前 active session 的用户/AI 对话中提取。
- 默认可认为短期上下文存在运行内存中，同时底层消息记录仍会落库或进入对应记录链路，便于恢复和审计。
- 主要服务当前聊天，不等同长期记忆。
- AI4ALL Account 创建后，开启该账号的第一个 session。
- Phase 1 只有两类 session 结束触发：每日凌晨 4 点 Dreaming，以及当前 session 超过 500 轮。
- Phase 1 不设置长时间未聊天等其他 session 结束逻辑。

### 3.2 长期但精简的常驻记忆

长期但精简的常驻记忆是 AI 每次和用户聊天时“应该立刻想起来”的信息。它类似现实中熟人之间不需要翻聊天记录就能记住的信息。

主体是 `MEMORY.md`，但逻辑上还包括一部分记录稳定设定和用户信息的 Context Files：

- `MEMORY.md`：精选长期记忆，例如长期偏好、重要背景、长期项目、重要关系、重要决定。
- `USER.md`：用户稳定资料和偏好，例如称呼、回复长短偏好、长期禁忌。
- `SOUL.md`：AI 的人格和陪伴风格，其中可能包含用户对 AI 人设的长期设定。
- `IDENTITY.md`：AI 对外身份和用户给 AI 设置的名字。

用途：

- 让 AI 不需要检索就能稳定体现关键个人化。
- 支撑用户对“它认识我”的基础感受。
- 避免把所有历史对话都塞进 prompt。

产品规则：

- 写入必须保守、精简、可追溯、可回滚。
- 用户明确设置的称呼、AI 名字、回复偏好优先进入对应 Context Files。
- Dreaming 可以把特别重要的信息写入 `MEMORY.md`。
- 超长 session 压缩不直接更新 `MEMORY.md`，只把重要信息延续到新 session。

### 3.3 需要检索和提取的历史记忆

这类记忆用于时间跨度特别长、聊天内容特别多、当前问题需要回想过往细节的场景。它不要求每次聊天都常驻 prompt，而是在需要时从历史记录中检索、提取、动态装载。

Phase 1 中，检索式记忆先作为可选能力处理：内测阶段实际触发频率预计较低，实现成本也明显高于基础 Dreaming 链路，因此优先保障 daily notes、session 压缩、Dreaming 和长期精简记忆的效果。

用途：

- 从长期历史里找出与当前话题相关的内容。
- 提升“你还记得之前我们聊过……”这类体验。
- 避免常驻记忆过大、过杂、污染普通对话。

产品规则：

- 基础来源是用户历史上的所有 daily notes。
- 技术上可以基于向量化检索、关键词检索、混合检索等方式实现，具体方案放到技术文档展开。
- 检索和提取可以异步进行；需要时动态装载到 prompt。
- 检索结果必须与当前聊天上下文相关，并受 token 预算、隐私和安全边界约束。
- 如果 Phase 1 未启用检索式记忆，不影响记忆机制主链路验收。

## 4. 存储实体与介质

| 实体/介质 | 对应逻辑层 | 产品含义 |
| --- | --- | --- |
| active session / messages | 短期上下文 | 当前 session 的用户和 AI 对话 |
| daily notes | 历史记录与检索记忆基础 | 以凌晨 4 点为日界线保存的每日原始聊天文字记录 |
| `MEMORY.md` | 长期精简记忆 | 每次聊天都应优先可用的精选长期记忆 |
| `USER.md` | 长期精简记忆 | 用户稳定资料、偏好、称呼和禁忌 |
| `SOUL.md` | 长期精简记忆 | AI 人格、陪伴风格和用户设定的人设 |
| `IDENTITY.md` | 长期精简记忆 | AI 名字、身份和对外自我描述 |
| 检索索引 | 需要检索和提取的历史记忆 | 基于 daily notes 的检索辅助数据，例如 embedding/index；Phase 1 可选 |

说明：

- daily notes 不等于 `MEMORY.md`。daily notes 更像历史材料，`MEMORY.md` 是精选后的长期记忆。
- `SOUL.md`、`USER.md`、`IDENTITY.md` 不全是“记忆文件”，但产品逻辑上属于 AI 长期稳定上下文的一部分。
- 检索索引不是用户可直接感知的记忆层，而是帮助 AI 从历史 daily notes 中找到相关内容的工具；Phase 1 可暂不建设完整索引能力。

## 5. 存储与处理过程

### 5.1 普通聊天过程

普通聊天时：

1. Backend 读取当前 active session 的短期上下文。
2. Backend 读取必要的 `MEMORY.md`、`USER.md`、`SOUL.md`、`IDENTITY.md`。
3. Backend 根据当前场景和 token 预算动态装载必要上下文；如果检索式记忆已启用，可装载相关 daily notes 或检索结果。
4. LLM 生成回复。
5. 回复成功后，对话记录默认沉淀到当前业务日的 daily notes。

daily notes 内容边界：

- 文本消息保存原始聊天文字。
- 语音消息保存上游语音转文字后的文本。
- 图片消息保存 AI 识别后的图片描述。
- daily notes 不保存原始图片本身。
- daily notes 不直接保存 Dreaming 摘要或结构化长期记忆；这些内容属于后续 Dreaming、`MEMORY.md` 或可选的检索索引链路。

业务日边界：

- daily notes 的一天从凌晨 4 点开始，到次日凌晨 4 点前结束。
- 例如 2026-05-25 03:30 的对话仍属于前一个业务日；2026-05-25 04:00 后进入新的业务日。

### 5.2 每日凌晨 4 点 Dreaming

每日凌晨 4 点触发 Dreaming 机制，对当前 session 进行压缩并结束旧 session。

处理规则：

- 当前 session 被压缩总结。
- 特别重要的信息写入或更新 `MEMORY.md`。
- 特别重要和比较重要的信息会延续到新开的 session，作为新 session 的起始上下文。
- 老 session 结束，新 session 开始。
- 当日对话记录默认已经保存到 daily notes，避免 Dreaming 遗漏时丢失历史材料。
- Dreaming 自动调度、自动应用/跳过、回滚机制和重要性判定标准放到 Dreaming 技术文档中定义。

产品目标：

- 每天自然切分对话上下文。
- 保持长期记忆精简。
- 让新一天的聊天不背负过长历史，但保留必要连续性。

### 5.3 超长 session 压缩

当前 session 超过 500 轮时，触发超长 session 压缩。

处理规则：

- 当前 session 被压缩总结并结束。
- 提取重要信息延续到新 session。
- 不更新 `MEMORY.md`，避免仅因 session 太长就污染长期精简记忆。
- 老 session 的对话记录仍保存在对应 daily notes 中，可供后续检索。

说明：

- “500 轮”默认指 500 个用户/AI 往返轮次，后续技术实现可进一步精确定义。
- 超长压缩服务于上下文窗口和对话连续性，不等同 Dreaming 的长期记忆晋升。

### 5.4 长期记忆 Dreaming

长期记忆主要通过 Dreaming 机制维护。详细 Dreaming 规则见 [Dreaming 记忆压缩与长期记忆技术设计](../architecture/designs/dreaming_memory_design.md)。

基本产品原则：

- 输入来源包括当前 session 压缩结果、daily notes、历史 Dreaming 记忆片段和用户明确设置。
- 只保留对未来长期有价值的信息。
- 去重、合并、删除过时或低价值信息。
- 用户明确纠正时，优先覆盖或删除旧记忆。
- 写入链路必须可追溯、可审计、可回滚。
- Dreaming 的自动调度、自动应用/跳过、回滚机制，以及“特别重要”“比较重要”的判定标准，放到 Dreaming 技术文档中定义。

### 5.5 检索式记忆

检索式记忆用于从长期历史里找当前相关内容。Phase 1 中该能力为可选项，不作为内测发布的必备条件。

基础过程：

1. 用户当前对话触发需要历史回忆的场景。
2. Backend 基于当前聊天上下文，在所有 daily notes 中检索相关内容。
3. 检索结果经过提取、压缩和安全过滤。
4. 相关片段被动态装载到 prompt。
5. AI 在回复中自然使用，不应机械展示“检索结果”。

处理要求：

- 可异步进行，避免阻塞普通聊天。
- 只装载与当前上下文相关的内容。
- 不把低置信、敏感或明显过时的内容强行注入。
- 检索命中和使用情况需要可观测，方便排查错误记忆。
- 若 Phase 1 暂不启用完整检索式记忆，daily notes 仍需按规范保存，作为后续补齐检索能力的历史材料基础。

## 6. 写入原则

- 所有记忆必须绑定 AI4ALL Account，严格账号隔离。
- 普通聊天成功后默认沉淀到 daily notes，不能阻塞用户回复。
- daily notes 是历史材料，不应未经筛选直接变成长期常驻记忆。
- Dreaming 写入 `MEMORY.md` 必须保守、可追溯、可回滚。
- 超长 session 压缩只延续新 session 上下文，不直接更新 `MEMORY.md`。
- 不把调试消息、一次性测试、失败回复或低价值寒暄晋升为长期记忆。
- 用户明确纠正时，应优先覆盖旧记忆、删除相关记忆或降低其权重。

## 7. Prompt 装载策略

不同记忆层进入 prompt 的方式不同：

- 短期上下文：默认装载当前 session 最近相关对话。
- 长期精简记忆：默认装载 `MEMORY.md` 及必要的 `USER.md`、`SOUL.md`、`IDENTITY.md`。
- 检索式记忆：Phase 1 可选；启用时按需检索，动态装载相关片段。
- daily notes：作为 Dreaming 和检索基础，不默认全量装载。

装载原则：

- 只装载当前回复真正需要的信息。
- 信息冲突时，用户最新明确纠正优先。
- 安全围栏高于所有记忆。
- 账号隔离高于所有检索和复用策略。

## 8. 用户体验

- 模型可以自然体现已知偏好，但不应频繁强调“我记住了”。
- 用户要求“记住”时，系统可以简短确认，但不得声称调用不存在的工具。
- 用户要求“不记这个”“删掉这个”时，应尊重并更新记忆状态。
- 用户跨天回来聊天时，AI 应保留必要连续性，但不应把昨日所有细节都强行搬出来。
- 用户提到久远话题时，如果检索式记忆已启用，AI 可以通过它增强回复；未启用时应避免编造。
- 敏感信息不应被主动诱导收集。

## 9. 运营需求

- Admin 能查看账号级 Context Files 的元数据、active session 摘要、daily notes 元数据和 `MEMORY.md` 摘要。
- daily notes 属于原始文字化聊天材料，默认不能在 Admin UI、Debug API 或日志平台直接展示正文。
- 如确需查看 daily notes 正文、语音转写正文、图片识别正文、用户聊天正文或模型回复正文，必须具备管理员最高权限，或具备管理员审批后的 2 小时临时明文权限，并记录操作日志。
- Admin 能运行或查看 Dreaming 任务状态、结果摘要、memory item 自动应用/跳过结果、diff 和审计记录，用于 debug 和调优。
- Admin 能禁用某账号记忆写入。
- Admin 能重置或删除某账号记忆。
- Admin 能查看 session 结束、Dreaming 和超长压缩记录；如果启用检索式记忆，还需要查看检索命中记录。
- 记忆变更需要可审计。

## 10. 验收标准

- 不同账号记忆不串线。
- AI4ALL Account 创建后能开启第一个 session。
- 普通聊天后 daily notes 可按凌晨 4 点业务日边界沉淀。
- daily notes 只保存文字化历史材料：文本原文、语音转写文本、图片 AI 识别描述，不保存原始图片。
- 每日凌晨 4 点 Dreaming 能结束旧 session，并开启新 session。
- Dreaming 能将特别重要的信息写入或更新 `MEMORY.md`。
- Dreaming 能将特别重要和比较重要的信息延续到新 session。
- 超过 500 轮的 session 会触发压缩，旧 session 结束，新 session 获得必要延续上下文。
- 超长 session 压缩不会直接更新 `MEMORY.md`。
- 记忆禁用、重置和查看至少在运营侧可用；涉及原始聊天材料或正文内容的查看必须具备管理员最高权限，或具备管理员审批后的 2 小时临时明文权限。
- 用户明确纠正某条记忆后，后续对话不继续使用旧错误记忆。
- 如果 Phase 1 启用检索式记忆，需要能基于历史 daily notes 找到与当前上下文相关的内容，并动态装载。

## 11. 待确认

- 检索式记忆的触发条件和用户可见体验。
- Phase 1 是否启用检索式记忆，以及启用到什么深度。
- 用户侧记忆管理入口的形态。
- 敏感记忆过滤规则。
- Dreaming 自动应用阈值、跳过规则和后台 debug 调优指标。
