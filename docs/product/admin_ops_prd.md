# 产品专题 PRD：运营与后台

更新时间：2026-05-28

## 1. 目标

为 Phase 1 内测提供基础运营、客服、观测和风控能力，让团队能排查绑定异常、对话异常、主动消息异常、权益误扣和用户反馈。

运营与后台能力必须优先保护用户隐私。后台不是查看用户私聊内容的工具，而是排查系统状态、账号关系、用量、错误和异常链路的工具。

## 2. 角色定位

运营、管理员、客服和研发不是本产品的目标用户，而是保障内测发布、服务稳定和用户支持的内部角色。

## 3. 隐私红线

后台默认不能查看用户具体聊天记录、语音转写正文、图片识别正文、raw payload 中的用户消息正文或模型回复正文。

Phase 1 通过后台用户权限分级控制明文访问：

- 普通后台用户只能查看元数据、统计、状态、摘要和脱敏结果。
- 管理员是最高权限角色，可以查看明文，用于必要 debug 和事故排查。
- 普通后台用户如确需查看明文，需要申请临时明文权限，由管理员审批。
- 临时明文权限有效期默认 2 小时，到期自动失效。
- 所有明文查看都必须记录操作人、时间、账号范围、资源范围和原因。

默认允许查看：

- 账号、绑定、会话和通道状态。
- 消息数量、时间、类型、状态、耗时、错误码、trace id 等元数据。
- 用量、权益扣减、模型调用成本、搜索成本和主动消息统计。
- 任务状态、失败原因、provider 状态和系统日志中的非正文信息。
- 聚合统计、异常计数、趋势、成功率、失败率等统计类信息。
- Context Files、daily notes、Dreaming、debug trace 和 prompt 相关视图默认只能展示元数据、摘要、状态、diff 摘要或脱敏结果，不展示用户聊天正文、模型回复正文或原始文字材料正文。

明文访问规则：

- 只有在严重安全事件、用户明确投诉且排查必须、合规/法务要求或重大线上事故等场景下，才应查看具体聊天内容或其他正文类敏感信息。
- 管理员拥有最高权限，但仍应遵守最小必要原则。
- 普通后台用户通过管理员审批后，只能在 2 小时有效期内查看被授权账号、时间范围和资源类型。
- 未经权限检查，不得通过 Admin UI、Debug API、数据库、日志平台或 raw payload 绕过该红线。

## 4. 功能需求

- 管理者可以查看账号、绑定、会话、消息元数据、用量和脱敏后的 raw payload 元数据。
- 管理者可以禁用/启用账号。
- 管理者可以调整基础 profile、默认风格和限流。
- 管理者可以查看提醒、主动消息、commitment 和 scheduler 状态。
- 管理者可以查看贝壳流水、拉新关系和基础客服处理记录。
- 如果开启支付，管理者可以查看订单和支付状态。
- Debug API 不应暴露到公网。
- 日志中不得保存明文密钥。
- Admin UI、Debug API 和日志平台默认不得展示用户聊天正文。

## 5. 关键视图

Phase 1 Admin 至少需要串起：

- `platform_users`
- AI4ALL Accounts
- `account_owner_bindings`
- `binding_intents`
- `channel_bindings`
- sessions
- message metadata / statistics
- raw payload metadata / redacted payload
- usage
- reminders / commitments / outbound messages
- entitlement ledger
- referral relationships
- support records

说明：

- `messages` 视图默认只展示消息 id、时间、类型、状态、耗时、错误、token、成本等元数据和统计，不展示聊天正文。
- `raw payload` 视图默认只展示通道、事件类型、路由、状态和错误等排障所需字段，不展示用户消息正文。
- `daily notes`、语音 ASR 文本、图片识别描述、prompt/messages、debug trace 详情和模型回复正文默认均按正文类敏感信息处理。
- 需要查看具体聊天内容或其他正文类敏感信息时，必须具备管理员最高权限，或具备管理员审批后的 2 小时临时明文权限。

## 6. 客服场景

- 处理绑定异常。
- 处理重复绑定或误绑。
- 处理账号禁用/恢复。
- 处理额度补发。
- 处理误扣排查。
- 记录用户反馈和基础工单。

客服处理原则：

- 优先通过账号状态、绑定状态、消息元数据、错误码、任务状态和用量流水排查。
- 不得要求用户提供验证码、密码、完整聊天截图等敏感材料。
- 如确实需要用户提供聊天上下文，应优先由用户主动截取并提供必要片段，而不是后台直接查看完整聊天记录。

## 7. 风控与观测

- 单个账号失败不能影响其他账号。
- 支持禁用账号或拉黑异常账号。
- 避免秒级高频回复、重复发送和批量触达。
- 支持基于元数据 trace 一条消息从接收到回复的链路。
- 支持查看 provider 错误和任务失败原因。
- 支持记录所有 Admin 访问、Debug API 调用和明文查看行为。

## 8. 验收标准

- 管理者能基于元数据追踪一条消息从接收到回复的链路。
- 管理者能查看账号、绑定、会话、消息统计/元数据和用量。
- 默认情况下，Admin UI、Debug API 和日志平台不展示用户具体聊天记录。
- 普通后台用户查看用户具体聊天内容必须有管理员审批后的 2 小时临时明文权限；管理员明文查看也必须记录操作日志。
- 管理者能处理绑定异常和账号禁用/恢复。
- 管理者能补发额度、查看邀请关系和排查误扣。
- 主动消息和任务失败能被定位到具体账号、任务和通道 route。
