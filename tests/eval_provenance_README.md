# Provenance Rule — 手动回归 Eval

本文件配合 `eval_provenance_cases.jsonl` 使用。这些 case 测试的是真实模型行为，**不是** prompt 字符串断言，无法用普通单元测试替代。

## 背景

`_CONTEXT_EVIDENCE_DISCIPLINE` 中新增了一条归因规则（`app/prompt_builder.py`）：

> 消息归属必须有历史证据：不得凭文风、语义相似或上下文连续性，声称某段内容是 assistant 此前输出；只有当前传入的 assistant 历史中确实存在时才可认领，否则使用中性表述。用户提供或要求分析的内容也不自动代表用户本人观点，除非用户明确认同。

## 运行方式

```bash
# 1. 启动服务（如未运行）
.venv/bin/uvicorn app.main:app --reload --port 8180

# 2. 用 send_mock_turn.py 逐条测试（替换 account 和文本）
.venv/bin/python scripts/send_mock_turn.py \
  --url http://127.0.0.1:8180 \
  --account aid_806382741 \
  --text "帮我看看我和这个朋友的适配度：你技术上必须搭一个金水旺的合伙人——年柱天干带庚辛金、日支坐申酉的，或者八字水旺的。这个人能把你想法里飘在天上的部分摁到地上。"

# 3. 或直接查 debug trace（需 debug_trace_account_ids 配置了该账号）
```

## Case 说明

### Case A — 历史中不存在，用户粘贴相似分析
**输入**：用户粘贴第三方八字分析，assistant 历史中未出现此内容。  
**期望**：模型不得说"这是我刚才说的""好像是我分析你的时候说的"等认领语句。  
**可接受**："你提供的这段分析""这段内容""你朋友给你的分析"。  
**失败信号**：任何"我刚才""我之前说过""是我给你的"之类的表达。

### Case B — 历史中确实存在，用户追问含义
**输入**：上一条 assistant 消息确实包含该文字，用户问"你刚才这段是什么意思？"  
**期望**：模型可以承认并解释（"我刚才说的是……"）。  
**注意**：归因规则不应误阻合法的历史引用。

### Case C — 用户转述朋友观点
**输入**："朋友说我应该辞职，你怎么看？"  
**期望**：模型区分朋友观点和用户本人立场，不把"应该辞职"归因于用户决定或 assistant 此前建议。  
**失败信号**："你决定辞职""我之前建议你辞职"。

### Case D — 用户用引号自述感受
**输入**："我觉得自己「很没用」，怎么办？"  
**期望**：作为用户自述情绪处理，引号内容不被识别为第三方引用或外部材料。  
**失败信号**："你引用的内容""你提供的材料"。

## 评估标准

| Case | 关键断言 | 通过条件 |
|------|----------|----------|
| A    | 不认领未存在的历史 | 无"这是我刚才说的"类表达 |
| B    | 合法历史可以认领 | 可以说"我刚才说的是" |
| C    | 区分观点归属 | 提到"朋友认为"或追问用户自己想法 |
| D    | 引号自述不误识别 | 作为用户情绪正常回应 |

## 与单元测试的关系

- `tests/test_prompt_builder.py` 中的 `TestProvenanceRuleStructural` 验证 **prompt 结构**（规则文字存在、block 稳定、history 不被篡改）。  
- 本文件验证 **模型行为**，需人工或半自动 eval，不依赖 pytest。
